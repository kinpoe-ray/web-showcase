Patterns · 三大模式

核心设计模式

让 monorepo 在规模增长时依然保持一致性。

pnpm Catalog
协议
所有依赖版本集中在一个文件。各 package.json 只写 catalog: 无需指定版本号。消除 monorepo 最大的敌人：版本漂移。
源码级
包解析
package.json 直接指向源码 ./src/index.tsx。开发时零构建步骤，改了 UI 包立刻在 web 应用中生效。
可组合
ESLint
base.js + next.js + rules/ 分层配置。强制通过 @campsite/ui 封装层引入第三方库，禁止绕过。

ESLint · AI 的隐形护栏

规则即约束

这些规则在 lint 阶段自动拦截 AI 生成的"坏代码"。
AI 不需要理解项目规范 — 它只需要通过 lint。

max-lines
文件不超过 500 行，强制拆分，保持代码可读性
500 · ERROR
no-unused-imports
零容忍死代码，自动删除未使用的导入
ERROR
no-console
禁止生产环境 console.log，杜绝调试残留
ERROR
consistent-type
统一使用 interface 定义类型，拒绝 type 混用
INTERFACE
restricted-imports
强制 UI 层封装边界，禁止直接引入第三方库
CUSTOM
exhaustive-deps
捕获缺失查询依赖，TanStack Query 专用规则
ERROR

06 / 08
TypeScript · 类型即文档

分层 TS 配置

strict mode 全面开启。路径别名指向源码而非 dist。编译期即捕获死代码和类型错误。

"TypeScript 严格模式让 AI 生成的代码在编译期就会被类型错误捕获。
类型系统本身就是最好的测试。"
/* 分层配置继承链 */

base.json
  └ strict: true
  └ declaration: true
  └ declarationMap: true

  ┐ nextjs.json
    └ noUnusedLocals
    └ noUnusedParameters
    └ incremental: true

      ┐ web/tsconfig.json
        └ strictNullChecks: true
        └ paths → source files
